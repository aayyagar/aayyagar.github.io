AD Tiering in 5 Steps

October 2026 · 7 min read · by Akhilesh Ayyagari

Most Active Directory compromises follow the same script: an attacker lands on a normal workstation, steals a cached credential, and finds that the same account — or one a short hop away — also administers a Domain Controller. The tiered administration model breaks that path. It is the single highest-impact change you can make to an AD environment, and you can roll it out in five steps.

The idea in one sentence

Separate your identities and the machines they log on to into tiers, and never let a high-tier credential touch a low-tier machine, where a low-tier attacker could steal it.

TierControlsExamples
Tier 0Identity & the keys to the kingdomDomain Controllers, AD CS, Entra Connect, Domain Admins
Tier 1Servers & applicationsFile, SQL, web and application servers
Tier 2Workstations & devicesUser laptops, VDI, help-desk endpoints

The rule is simple: a Tier 0 admin account signs in only to Tier 0 systems. If a Domain Admin ever logs on to a user's laptop to "fix something," that laptop can now steal a Domain Admin credential, and the model is broken.

Step 1 — Inventory what belongs in Tier 0

You cannot protect a boundary you have not drawn. List every system that can control identity: Domain Controllers, the AD Certificate Services CA, Entra Connect / AAD Connect servers, your privileged access management vault, and any server holding the credentials of a Tier 0 account. This list is almost always larger than people expect — a backup server that can restore a DC is effectively Tier 0.

Step 2 — Create separate admin accounts per tier

Give each administrator distinct accounts: a normal user account for email and daily work (Tier 2), and separate admin accounts for the tiers they manage. A naming convention makes this auditable:

jsmith        # daily driver, no admin rights
jsmith-t1     # Tier 1 server admin
jsmith-t0     # Tier 0 / Domain Admin

Put each admin account in a tier-specific OU and group. Nobody uses jsmith-t0 to read email.

Step 3 — Enforce the boundary with logon restrictions

Good intentions are not a control. Enforce the separation technically so a tier violation is impossible, not just discouraged:

  • Group Policy "Deny log on" rights — deny Tier 0 accounts the ability to log on to Tier 1 and Tier 2 machines, and so on down.
  • Authentication Policy Silos (Windows Server 2012 R2+) — bind Tier 0 accounts to Tier 0 hosts at the Kerberos level, so a ticket for them is only usable on Tier 0 systems.
  • The Protected Users group — add Tier 0 accounts to limit credential caching and force stronger Kerberos.
Why this stops the attack: even after an attacker fully owns a Tier 2 laptop, no Tier 0 or Tier 1 credential is ever present on it to steal. The lateral-movement path up to the Domain Controller simply is not there.

Step 4 — Give admins Privileged Access Workstations

A Tier 0 admin needs a clean machine to work from — one that does not browse the web or read email, where malware cannot ride in. A Privileged Access Workstation (PAW) is a hardened, locked-down device used only for privileged tasks. Tier 0 administration happens from a PAW, full stop. This is the step people skip, and it is the one that makes the rest real.

Step 5 — Add just-in-time access and monitoring

Standing admin rights are standing risk. Move day-to-day privilege to just-in-time activation — Microsoft Entra Privileged Identity Management in the cloud, or a PAM tool on-prem — so an account is only privileged for the window it is actually needed, with approval and MFA on activation. Keep permanent membership in Tier 0 groups down to a couple of monitored break-glass accounts, and alert whenever they sign in.

Where to start tomorrow

You do not need all five steps live before you get value. Do them in order, and each one closes a real door:

  1. Inventory Tier 0 — you now know what to protect.
  2. Separate admin accounts — daily work stops exposing admin credentials.
  3. Logon restrictions — the lateral path is cut.
  4. PAWs — privileged work happens on clean machines.
  5. JIT + monitoring — standing privilege shrinks to near zero.

Tiering is not a product you buy; it is a discipline you enforce. But it is the discipline that turns a single stolen laptop from a domain-wide disaster into a contained incident.
